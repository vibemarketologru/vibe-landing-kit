# Свой стиль из брендбука клиента → запись дизайн-системы

Каталог Vibe Landing Kit описывает эстетику чужих брендов и общие стили. Этот навык делает
запись по брендбуку ВАШЕГО клиента: тот же формат (`SCHEMA.md`), та же машинная проверка
(`tools/check.mjs`), после чего любой агент верстает лендинги клиента без вопросов, в обеих темах и
с проверенным контрастом.

Идея порядка работы — из [bergside/awesome-design-skills](https://github.com/bergside/awesome-design-skills)
(MIT): намерение → токены → анатомия и состояния → доступность и тон → антипаттерны → чек-лист,
правила формулируются как «must / should» с примером «не делай». Содержание, пороги и формат —
наши.

## Что собрать на входе

| Материал | Зачем | Если нет |
|---|---|---|
| Брендбук (PDF) | цвета, шрифты, тон, запреты | снять с живого сайта клиента (см. ниже) |
| Цвета в HEX | точные значения | Pantone и CMYK не переводить на глаз — брать HEX из брендбука или с сайта |
| Шрифты и их лицензия | можно ли отдавать с сайта | заменить свободным (шаг 2) |
| Логотип SVG | на страницу клиента — файлом | в запись дизайн-системы логотип НЕ входит |
| 5–10 фото бренда | стиль съёмки для `media` | описать желаемую съёмку словами |
| Тексты сайта, рассылок | голос бренда | пройти интервью из 3 вопросов (шаг 4) |

Цвета с живого сайта — из вычисленных стилей (`getComputedStyle` кнопки, фона, текста), а не
пипеткой со скриншота: сжатие и цветовой профиль сдвигают оттенок.

Внимание: брендбук часто конфиденциален. Запись по нему храните в своём приватном проекте, а не в
публичном форке. Проверка работает на любой папке с подкаталогом `design-systems/`.

## Шаг 1. Намерение одной фразой

До любых цветов — одно предложение: для кого страница и какое чувство она оставляет.

> «Семейная стоматология у дома: спокойно, по-человечески, цены видно сразу».

Каждое следующее правило проверяется на соответствие этой фразе. Правило, которое ей мешает, —
вычеркнуть. Фраза идёт в `summary` (до 400 символов) вместе с тем, из чего складывается вид.

## Шаг 2. Токены

### Цвета: 12 ролей × 2 темы

Роли — `background`, `surface`, `text`, `text_muted`, `border`, `primary`, `on_primary`, `accent`,
`on_accent`, `link`, `success`, `error`. Обе темы заполняются целиком.

Пороги `check.mjs` (обязательны в светлой И тёмной теме):

| Пара | Минимум |
|---|---|
| `text` / `background` | 7 : 1 |
| `text` / `surface` | 4,5 : 1 |
| `text_muted` / `background` | 4,5 : 1 |
| `on_primary` / `primary` | 4,5 : 1 |
| `on_accent` / `accent` | 4,5 : 1 |
| `link` / `background` | 4,5 : 1 |

Как разложить фирменные цвета по ролям:

1. Главный фирменный цвет → `primary`. Это **заливка** кнопки, а не цвет текста.
2. `on_primary` подбирается под заливку: белый или почти чёрный — что даёт ≥ 4,5.
   Фирменный оранжевый `#FF6A13` с белым даёт 2,87 — не проходит; с `#1A1A1A` — 6,07, проходит.
   Значит, текст на оранжевой кнопке тёмный, и это нормально.
3. Фирменный цвет, который по фону страницы даёт меньше 4,5, никогда не идёт в текст, ссылки и
   цифры. Для ссылок — отдельный `link`: затемнённый (светлая тема) или осветлённый (тёмная) оттенок
   фирменного, пока не пройдёт 4,5.
4. Второй фирменный цвет → `accent` (бейджи, выделения, второй тип кнопки) с `on_accent`.
5. `success` и `error` не берутся из палитры бренда, если там нет подходящих: красный бренда в роли
   ошибки путает человека.

Тёмную тему проектируют, а не инвертируют:
- фон — не чистый чёрный, а тёмный нейтральный с оттенком бренда; поверхность светлее фона на ступень;
- `primary` в тёмной теме обычно светлее и чуть менее насыщен, чем в светлой, — проверяется парой с `on_primary`;
- `text` — не чистый белый, а слегка приглушённый, при этом ≥ 7 : 1 к фону.

Быстрая проверка пар до сборки всей записи:

```js
// node pairs.mjs '#FFFFFF' '#1F5C4A' '#1A1A1A' '#FF6A13'  — пары «текст фон»
const lum = h => { const n = parseInt(h.slice(1), 16); return [n >> 16 & 255, n >> 8 & 255, n & 255]
  .map(v => (v /= 255) <= 0.03928 ? v / 12.92 : ((v + 0.055) / 1.055) ** 2.4)
  .reduce((s, v, i) => s + v * [0.2126, 0.7152, 0.0722][i], 0); };
const ratio = (a, b) => { const [x, y] = [lum(a), lum(b)].sort((p, q) => q - p); return (x + 0.05) / (y + 0.05); };
const a = process.argv.slice(2);
for (let i = 0; i + 1 < a.length; i += 2) console.log(a[i], 'на', a[i + 1], '=', ratio(a[i], a[i + 1]).toFixed(2));
```

### Шрифты: только свободные и с кириллицей

Фирменные шрифты почти всегда нельзя отдавать с сайта клиента без веб-лицензии, и у многих нет
кириллицы. Замена — шрифт с лицензией OFL-1.1 (или Apache-2.0) и подмножеством `cyrillic` из
Fontsource. Проверка одного шрифта:

```bash
curl -s https://api.fontsource.org/v1/fonts/onest | node -e "let s='';process.stdin.on('data',d=>s+=d).on('end',()=>{const f=JSON.parse(s);console.log(f.family,f.license,f.subsets.includes('cyrillic')?'кириллица есть':'НЕТ КИРИЛЛИЦЫ',f.weights.join(','))})"
```

Список всех семейств с кириллицей: `https://api.fontsource.org/v1/fonts?subsets=cyrillic`.

| Характер фирменного шрифта | Замены с кириллицей (OFL, проверено 24.09.2026) |
|---|---|
| Нейтральный гротеск | Inter, Onest, Golos Text, Geist, Manrope, Inter Tight |
| Геометрический | Montserrat, Manrope, Unbounded (только заголовки) |
| Мягкий, округлый | Nunito, Nunito Sans, Comfortaa (только заголовки), Rubik |
| Узкий, плакатный | Sofia Sans Condensed, Roboto Condensed, Oswald |
| Антиква для текста | Lora, PT Serif, Literata, Source Serif 4 |
| Контрастная антиква для заголовков | Playfair Display, Cormorant |
| Моноширинный | JetBrains Mono, IBM Plex Mono |
| Рукописный акцент | Caveat (одно-два слова, не абзацы) |

Популярные шрифты **без кириллицы** (не брать для русских страниц): Plus Jakarta Sans (только
cyrillic-ext), DM Sans, Poppins, Outfit, Space Grotesk, Sora, Urbanist, Lexend, Figtree, Work Sans,
Bricolage Grotesque, Instrument Serif, DM Serif Display.

Правила: шрифты отдаёт сервер клиента (`@fontsource-variable/<id>` из npm или свои `woff2`),
никогда Google Fonts и чужие CDN. Знак ₽ (U+20BD) лежит в подмножестве `latin-ext`, № — в
`cyrillic`: подключайте оба, иначе рубль нарисуется системным шрифтом. Цены и таблицы —
`font-variant-numeric: tabular-nums`. Каждый вес из `fonts[].weights` должен существовать у шрифта.

### Типографика, отступы, радиусы, движение

- Роли `display`, `h2`, `h3`, `body`, `caption`, у каждой `size_desktop` и `size_mobile`;
  `body` на телефоне ≥ 16 px; текст в полях ввода — тоже не меньше 16 px, иначе Safari на iPhone
  увеличивает страницу при фокусе на поле.
- `radius` (`sm`, `md`, `lg`, `pill`), `spacing` (шаг, отступ секции десктоп/телефон, контейнер,
  боковое поле на телефоне), `shadow` (`card`, `raised`), `motion` (длительности и кривые).
- Значения — из брендбука, если он их задаёт; нет — из характера: строгий бренд — радиусы 0–6 px,
  тёплый — 16–24 px и пилюли.

## Шаг 3. Анатомия и состояния компонентов

Компоненты записи: `button_primary`, `button_secondary`, `card`, `input`, `badge`, `nav`. У
интерактивных — все состояния конкретными значениями, а не прилагательными:

| Состояние | Кнопка — пример значения | Поле — пример значения |
|---|---|---|
| default | фон `primary`, текст `on_primary`, высота 52 px, пилюля | рамка 1 px `border`, высота 52 px |
| hover | фон на 8 % темнее за 160 ms, тень `card` → `raised` | рамка `text_muted` |
| focus-visible | обводка 3 px `link`, отступ 3 px — видна с клавиатуры | обводка 2 px `link` + тень-кольцо |
| active | `scale(0.98)` | — |
| disabled | прозрачность 0,5, без тени; рядом текст причины | фон `surface`, текст `text_muted` |
| loading | текст «Отправляем…», повторный клик игнорируется скриптом | — |
| error | — | рамка `error` + текст ошибки под полем словами, не только цветом |

Обводка фокуса и граница поля должны отличаться от соседнего фона не меньше чем на 3 : 1 (WCAG
1.4.11, 2.4.7): бледная граница поля на белом — частая потеря.

**Русский текст длиннее английского на 20–30 %.** Состояния проверяются на длинных подписях, а
не на «Submit»:

- кнопки: «Записаться на бесплатную консультацию», «Получить расчёт стоимости ремонта»;
- поле: «Удобное время для звонка (необязательно)»;
- ошибка: «Проверьте номер телефона: в нём должно быть 10 цифр после +7»;
- пункт меню: «Стоимость и сроки».

Правила: у кнопки нет фиксированной ширины — на 360 px длинная подпись переносится на две строки,
а не вылезает; `min-height` ≥ 44 px; ЗАГЛАВНЫЕ с разрядкой удлиняют строку ещё сильнее — только для
коротких надзаголовков; в узких карточках — `hyphens: auto` при `lang="ru"`.

## Шаг 4. Доступность и голос

Доступность — проверяемыми критериями:
- контраст пар — по таблице шага 2 в обеих темах;
- зоны нажатия ≥ 44 × 44 px, между ними ≥ 8 px;
- фокус виден на каждом интерактивном элементе;
- ошибки формы — текстом и `aria-describedby`, не одним цветом;
- `prefers-reduced-motion`: движение из `motion_recipes` смягчается или убирается.

Голос — три вопроса клиенту: как вы обращаетесь к клиенту («вы» или «Вы», по имени?); какие три
слова про вас правда, а какие три — нет; каких фраз вы никогда не пишете. Из ответов — 1–3
предложения голоса и пары «так / не так»:

| Так | Не так |
|---|---|
| «Назовём цену до начала лечения» | «Прозрачное ценообразование» |
| «Перезвоним за 15 минут» | «Оперативная обратная связь» |

## Шаг 5. Антипаттерны: must / should + пример «не делай»

«must» — нарушение ломает запись или закон; «should» — рекомендация с объяснением. Каждое
правило «делай» получает хотя бы один пример «не делай». В запись они уходят как `do` и `dont`
(по 4–7 пунктов, конкретно).

| Правило | Сила | Не делай |
|---|---|---|
| Фирменный цвет с контрастом < 4,5 к фону — только заливка | must | оранжевые цены на белом фоне |
| Один насыщенный цвет действия на странице | should | три разноцветные кнопки в одном экране |
| Текст на фото — только на затемнении | must | белый заголовок прямо по светлому небу |
| Шрифты — свои файлы с кириллицей | must | Poppins из Google Fonts |
| Логотип — файлом клиента в вёрстке, не рисунком модели | must | «логотип в стиле бренда», сгенерированный нейросетью |
| Не копировать оформление конкурента в той же нише | must | кофейня в зелёном круге «как у известной сети» (135-ФЗ ст. 14.6, навык `landing-law-ru`) |
| Ошибки — словами | must | красная рамка без текста |

Если в проекте уже есть страницы в старом стиле, добавьте заметку о переходе: что заменить
первым (кнопки, поля, шрифты) и что может жить по-старому до переделки.

## Шаг 6. Сборка записи и машинная проверка

Файл `design-systems/<slug>.json` по `SCHEMA.md`, обязательные поля:
`slug` (латиница, kebab-case, равен имени файла), `name`, `kind: "style"`, `version`,
`disclaimer` (чей брендбук, с разрешения клиента, без логотипа), `summary` (≤ 400), `summary_en`,
`best_for`, `goals`, `mood`, `tokens` (цвета обеих тем, типографика 5 ролей, radius, spacing,
shadow, motion), `fonts` (семейство, id Fontsource, роль, веса, что заменяет), `components`,
`layout` (`hero_pattern`, `section_order`, `grid`, `mobile_notes`), `lead_form` (с
`consent_152fz: true`, галочка не отмечена заранее), `motion_recipes` (2–4 слага из `motion/`) и
`motion_map` на каждый, `media` (`hero`, `video_in_flow`, `imagery`, `character`, `audio`, `avoid[]`),
`ab_axes` (`vary`, `fixed`, `default` для каждой оси + `legend`/`notes`), `do`/`dont` по 4–7,
`prompt_snippet` (английский абзац 80–150 слов для верстальщика-модели), `source`
(`inspired_by`: «брендбук <клиент>, версия, дата»).

`kind: "style"`, а не `brand`: `brand` в каталоге значит «эстетика в духе чужого мирового бренда».

Проверка — пока каждая запись не даст `OK`:

```bash
node tools/check.mjs . <slug>
```

Типичные ответы и что делать:

| Ответ проверки | Лечение |
|---|---|
| `контраст dark on_primary/primary = 3.10 < 4.5` | поменять `on_primary` тёмной темы или осветлить/затемнить `primary` |
| `шрифт X: НЕТ кириллицы` | взять замену из таблицы шага 2 |
| `шрифт X: нет начертания 800` | убрать вес из `fonts[].weights` или взять другой шрифт |
| `typography использует X, которого нет в fonts` | добавить шрифт в `fonts` или поправить роль |
| `motion_recipes: нет рецепта …` | слаг только из `ls motion/` |
| `ab_axes.default: нет оси …` | задать значение варианта A для каждой оси |
| `media.… пусто` | заполнить все пять строк и список `avoid` |

Без слага проверка сверяет ещё и `catalog.json`; в своём форке его пересобирает
`node tools/build-index.mjs .`, руками он не правится.

## Шаг 7. Чек-лист перед сдачей

- [ ] Намерение одной фразой записано и не противоречит ни одному правилу.
- [ ] `node tools/check.mjs . <slug>` → `OK` с таблицей контраста обеих тем.
- [ ] Шрифты — OFL с кириллицей, отдаются своим сервером, ₽ и № рисуются этим шрифтом.
- [ ] У кнопки и поля описаны все состояния, включая focus-visible, loading и error.
- [ ] Длинные русские подписи проверены на 360 px: ничего не вылезает, кнопки ≥ 44 px.
- [ ] Демо-страница открыта в обеих темах на 1280 и 390 px и просмотрена глазами — стиль узнаётся
      как стиль клиента, а не как «ещё один SaaS».
- [ ] В записи нет логотипа, фирменных фото и приёмов, выросших из логотипа конкурента.
- [ ] Запись с конфиденциальным брендбуком лежит в приватном репозитории.
